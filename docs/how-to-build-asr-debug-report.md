# ASR 调试页面生成指南

供 AI 调查 ASR（语音识别）的复读、无声续写、漏字和流式状态问题。产物是一份可离线打开的交互式 HTML 报告：按轮次展示音频、mel、声音向量、解码请求、KV cache、输出 token 和历史提交，支持音频试听与真实数值检查，用于定位第一次错误及其传播过程。

## 用户最少提供什么

在 AI 已能访问目标项目、模型和运行环境的前提下，用户只需提供**可访问的问题音频文件或路径**，即可开始采集；也可提供包含音频和必要快照的完整证据目录。对话中已经提供的信息不要重复询问。

- **可选信息：** 异常现象、大致时间范围、错误文字或期望文字。没有时间点时，AI 从实际运行结果中查找疑点。
- **仅缺失时询问：** 无法定位目标项目、音频不可访问，或存在多个实现/模型且无法确定实际使用哪一个时，集中询问缺失信息。
- **AI 自行确定：** 从代码、设置和日志核对模型、配置、入口及采集能力；选择必要轮次、输出位置和页面布局。无需用户提供 mel、KV、张量维度或页面设计。
- **未复现时：** 可以展示实际运行的代表性轮次，但明确标注尚未复现异常，不编造错误位置或根因。

## 工作原则

- 先阅读当前实现，从实际配置和采集数据确定时间、维度、token 数量及模型参数。
- 优先用 CLI 复现，区分实时录音、文件流式回放和整段转录。
- 保留原实验，每个对照单独记录；一次只改一个因素。
- 明确区分原始采集、后来重放、计算推导和人工标注。

## 执行步骤

1. **固定实验。** 记录音频范围、样本率、模型与权重哈希、tokenizer、精度、LoRA、语言、回退数量、生成预算、实际命令及源码/二进制版本。
2. **定位第一处分歧。** 检查原始输出 token，而不只看最终文字。选取错误前、首次错误、错误传播的连续轮次；保留恢复这些状态需要的前序上下文。
3. **补齐采集。** 每轮保存实际 PCM、mel、encoder 输出、完整请求 embedding、模板与历史 token、逐 token 分数和终止原因、提交前后的历史、最终显示文字。用唯一 decode ID 串联事件。
4. **采集 KV。** 保存裁切前、裁切后、prefill 后、decode 后的有效 K/V；必要时保存每个 token 新增的行。记录各层 shape、dtype、offset、公共前缀和 reset。
5. **缺失数据时重放。** 若原运行没有保存 KV，用相同权重和连续请求按原顺序自由生成，核对 token、logits 和 offset。不能强行喂预期答案后宣称重现；重放失败时保留第一处分歧。
6. **整理与画图。** 将证据转换为可检查的数据，绘制完整流程、窗口、请求区域、KV 生命周期、输出及跨轮反馈。布局和标签从实际数据生成。
7. **验证并交付。** 核对数值、索引、来源、交互和离线打开；说明已证实的结论、尚未确定的原因和下一项对照实验。

## 所需数据如何取得

先检查现有 CLI 和日志是否已保存所需数据。没有时，在实际推理路径加入受诊断开关控制的采集点，重新编译并用 CLI 回放；最终转录文本不能替代中间状态。以下函数名用于定位当前项目，其他项目寻找等价位置。

| 数据 | 采集位置与时机 |
|---|---|
| 模型与配置 | 从实际加载的模型目录、运行参数和生效配置读取；保存权重、tokenizer、配置、源码与二进制哈希。 |
| PCM 与时间轴 | 在 `StreamingInferenceSession.feedAudio` 入口保存实际收到的样本，已包含此前的混音、重采样和裁切；记录批次起止样本、补零、排除区间及原录音映射。 |
| mel | 在增量 mel 输出处记录新帧，并在 encoder 调用前保存本轮实际使用的完整 mel、窗口边界与前处理参数；不要用另一套离线默认算法代替。 |
| 声音向量 | 在 `assembleAudioFeatures` 返回后保存完整窗口和尾部拼接结果；若送入请求前转换 dtype，同时记录实际使用的转换结果。 |
| 解码请求 | 在调用 `prefillWithEmbeddingDiff` 前保存完整 `inputsEmbeds`、基础 `inputIds`、单独追加的前缀 IDs、文字历史及各区域边界。 |
| KV 与复用边界 | 在 `prefillWithEmbeddingDiff` 中记录输入公共前缀、各层 offset；从 `KVCache.state` 导出裁切前、裁切后、prefill 完成后的有效 K/V。 |
| token、分数、终止原因 | 在 `decodeTokens` 每次选出候选后、判断 EOS 前记录 ID、位置、选中分数及所有 EOS 候选分数；循环退出时明确记录 EOS、预算、取消或错误。需要概率时另存归一化信息。 |
| 逐 token KV | 每个非 EOS token 回送 decoder、前向计算完成后保存新追加的 K/V 行；本轮结束再保存完整有效缓存。 |
| 历史与显示 | 在重复检查和 committer 更新前后保存决策、历史、确认/暂定/已输出 token；在 `displayUpdate`、最终结束事件处保存实际显示文字，并记录 reset、final 与 flush。 |

张量以 Safetensors 等保留 dtype 和原始字节的格式保存；事件用 NDJSON，PCM 用 WAV。用会话 ID、唯一 decode ID、阶段和 token 位置关联文件，记录 shape、轴顺序、时间范围及哈希。MLX 等惰性框架须在对应计算完成后立即序列化，不能把仍会变化的缓存引用当作快照。

若只有音频和最终文字，重新运行完整链路补采；若已有连续请求 embedding，可只重放 decoder 补 KV，但必须恢复相同前序状态并验证输出。将原始证据转换为页面数据时保留来源，缺失项明确标注，不从长度或文字猜出张量值。

## 页面必须包含

- 完整流程：音频 → PCM → mel → encoder → 请求 → KV 复用/裁切 → prefill → decode → 提交 → 显示。
- 本轮循环：选出非 EOS token 后回送 decoder，读取并追加 KV，计算下一个 token；下一轮请求变化后再次 prefill。
- 原音频 PCM16 试听与实际 mel 反向重建试听，使用相同时间区间；重建不能使用 TTS 或原音频相位冒充。
- 真实 mel、声音向量、模板、历史前缀、回退内容、逐 token 输出和分数。
- KV 的阶段切换、层/头/位置/维度选择、真实数值及有效范围。
- 原录音时间、裁片时间、样本、mel 帧、请求行和 token 编号的对应关系。
- 数据来源、哈希、实验配置和证据限制。未采集或已裁出的值不能显示成 0。

## 页面生成的关键方法

1. **统一数据结构。** 以 decode ID 组织轮次；每个张量保留 shape、dtype、轴顺序、原始字节和来源。时间、窗口、模板边界和交互范围从数据生成，避免写死。
2. **流程图。** 用 HTML/SVG 绘制节点和方向箭头；点击节点显示输入、输出、保留状态，并跳转对应数据。分别画出本轮 token 循环、跨轮文字历史和 KV 反馈。
3. **张量热图。** 用 Canvas 绘制 mel 的时间×频带、embedding 的位置×维度、选定层/头的 K/V 位置×维度。BF16 按位扩展为 Float32；点击坐标直接索引原数组。对照图使用统一色阶，颜色截断不得改变显示的真实数值。
4. **请求与 token。** 按实际边界展示模板、声音和文字前缀；token ID、分数、保留/回退状态与日志逐项关联。文字使用对应 tokenizer 累计解码，避免把日语字节片段误当完整字符；日志文本按纯文本展示。
5. **KV 阶段视图。** 按捕获阶段的有效长度切换。逐 token 视图可由已验证的 prefill 快照与新增行构造；相同前缀去重存储，但索引映射必须来自实际数据。区分逻辑裁切和底层容量，不展示失效区为有效值。
6. **mel 反向试听。** 按实际前处理公式反归一化，还原 mel 能量；用相同滤波组做非负最小二乘（NNLS）得到线性功率谱，开方后用随机相位 Griffin–Lim 重建。匹配 FFT、hop、窗函数和 padding，记录种子与误差；另由原 PCM 生成 PCM16 对照轨。
7. **交互联动。** 用统一选中轮次同步所有视图；KV 层/头/阶段/位置与数值检查器联动。切换轮次、窗口或音轨时停止旧播放，按音频时钟在区间末尾停止；异步解压完成后检查选择是否仍有效。
8. **离线打包。** 将样式、交互、数据和 WAV 内嵌到一个 HTML；大张量按层无损压缩并按需解压，避免巨大单一 JSON 节点。正确转义内嵌 JSON，检查占位符、DOM ID、数据长度、控制台错误及断网后的试听和读数。

## 验收重点

- 请求中的声音区域确实来自 encoder 输出；文本与原始 token IDs 一致。
- KV 保留区、prefill 新增区、逐 token 追加区及跨轮状态吻合；考虑实际 reset 和缓存策略。
- 轮次切换同步更新全部视图；试听在选定区间结束；热图索引与抽样数值一致。
- KV 不是 attention 权重，logits 不是幻觉概率；mel 重建有损，不能当作精确原音频。
- 区分错误产生与错误传播：删除旧 KV 后，错误文字仍可能通过历史前缀重新进入模型。
- 调查暂停漏字时，额外检查 final、flush、暂定区和结束事件。
